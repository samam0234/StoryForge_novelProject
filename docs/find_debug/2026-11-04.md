## 1. 프론트가 빌드되지 않은 채 main까지 올라감

- **증상**: `ng serve`가 `NG5002: Unexpected closing tag "div"`로 실패.
- **원인**: 함께 창작 커밋 `538cb59`가 `create.page.ts`에 닫는 태그를 하나 더 넣음. **`npx ng test`는 통과했습니다.** 테스트 빌드는 spec이 가져오는 파일만 컴파일하는데 이 화면을 가져오는 spec이 없습니다. 이 커밋이 `develop`과 PR #4로 원격 `main`까지 들어갔습니다.
- **해결**: `edbc036`에서 수정. 이 수정은 `feature/auth` → `develop`까지 반영했고, 원격 `main`에는 아직 없습니다.
- **재발방지**: `ng build`를 정본과 체크리스트의 필수 확인으로 올렸습니다. 화면을 바꾸면 `ng test`만으로 끝내지 않습니다.

## 2. AI 테스트 1건이 이미 깨져 있었음

- **증상**: `test_collab_action_has_no_url_here` 실패.
- **원인**: 같은 커밋에서 `/콜라보` 응답의 첫 버튼이 "창작하기"로 바뀌었는데 테스트는 첫 버튼을 콜라보로 가정함.
- **해결**: 콜라보 버튼을 찾아서 검사하도록 수정(`7ba9a61`). 동작 문제는 아니었습니다.

## 3. 알림 창과 좁은 화면의 상단바

- **증상**: 알림 창의 "모두 읽음"이 잘림. 폭 390px에서 이름이 로고와 겹치고 로그아웃 버튼이 밀려남.
- **원인**: 메뉴 최대 폭보다 큰 `min-width`. 좁은 화면의 상단 항목 합계가 화면 폭을 넘음.
- **해결**: `min-width` 제거, 600px 이하에서 이름 숨김.

## 4. 에디터의 tsconfig 오류 표시

- **증상**: VS Code가 `tsconfig.app.json`, `tsconfig.spec.json`의 `outDir`에 `rootDir` 오류를 표시 (TypeScript 6 언어 서버).
- **해결**: `rootDir: ./src`를 명시. 빌드와 테스트 결과에는 영향이 없습니다.
