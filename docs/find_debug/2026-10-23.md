## 1. VS Code Java 경고 정리 (null 안전성)

- **증상**: 백엔드 파일에 노란줄. 대부분 `Null type safety: ... needs unchecked conversion to conform to '@NonNull ...'`, 그리고 `PipelineOrchestrator`의 `Potential null pointer access: The variable prepared may be null`.
- **원인**: Spring은 파라미터에 `@NonNull`을 붙여 두었는데, 우리 코드는 null 여부를 표시하지 않아 VS Code(Eclipse JDT)가 경고합니다. `TransactionTemplate.execute()`는 실제로 `@Nullable`을 반환하므로 `prepared` 경고는 진짜 결함 가능성이었습니다.
- **해결**:
  - 라이브러리를 호출하는 지점에서 `Objects.requireNonNull(...)`로 확인합니다.
  - 트랜잭션 결과는 `inTx()` 헬퍼로 null 검사를 한 곳에 모았습니다.
  - SSE 이벤트 값은 한 번만 읽어 지역 변수에 담습니다 (`requireNonNullElse`).
  - `@Bean` 메서드는 `public`을 뺐습니다 (Spring 도구 힌트).
  - 패키지 전체에 `@NonNullApi`를 붙이는 방법도 시험했지만, 경고가 컨트롤러·오케스트레이터로 번져서 되돌렸습니다.
- **재발방지**: Spring API에 값을 넘길 때 null일 수 있는 반환값(`execute`, `event.data()` 등)은 바로 검사합니다.
- **남긴 것**: `pom.xml`의 "Spring Boot 3.5.x OSS 지원 종료" 경고는 기획서 §12(3.x 지정) 때문에 유지합니다. 4.x 전환은 사용자 결정 대기입니다.

## 2. 통합 테스트 중 AI 서비스 502

- **증상**: Bible 생성이 502. AI 서비스 `uvicorn`은 시작하자마자 종료됨.
- **원인**: 다른 프로젝트의 Django 개발 서버가 `127.0.0.1:8000`을 쓰고 있어, 백엔드 요청이 그 서버로 갔습니다.
- **해결**: AI를 8001로 띄우고 백엔드를 `AI_SERVICE_URL=http://localhost:8001`로 실행했습니다. Django 서버는 건드리지 않았습니다.
- **재발방지**: [../repeater/local-port-conflicts.md](../repeater/local-port-conflicts.md)에 정리했습니다.

## 3. 백엔드 재시작 실패 (8080 사용 중)

- **증상**: `Port 8080 was already in use`.
- **원인**: `./mvnw spring-boot:run`을 띄운 셸을 종료해도 자식 JVM(`StoryforgeApplication`)이 남아 있었습니다.
- **해결**: 명령줄에 `StoryforgeApplication`이 있는 프로세스인지 확인한 뒤 PID로 종료했습니다.
- **재발방지**: 위 repeater 문서에 확인 명령을 남겼습니다.
