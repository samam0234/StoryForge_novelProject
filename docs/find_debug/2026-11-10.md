## 1. 동일 작성자의 여러 신고를 일괄 정지하면 전체 롤백

- **증상**: 같은 작성자가 쓴 서로 다른 게시글 두 개의 대기 신고를 선택하고 `SUSPEND`를 요청하면 200 대신 409가 반환되고 조치가 모두 취소됐습니다. 회귀 테스트 `batchCanSuspendAndUnsuspendSameAuthorAcrossDifferentTargets`로 수정 전 실패를 재현했습니다.
- **원인**: 같은 콘텐츠 대상의 중복만 제거했습니다. 첫 대상에서 작성자를 정지한 뒤 두 번째 대상도 같은 계정을 정지하려고 하자, 요청 내부에서 만든 상태 변경을 다른 요청의 충돌로 오인했습니다. `UNSUSPEND`도 같은 구조였습니다.
- **해결**: 일괄 트랜잭션에 한정해 변경한 계정 ID를 공유합니다. 계정 변경과 작성자 알림은 한 번만 실행하고, 각 대상의 신고 결과·신고자 알림·감사 기록은 따로 남깁니다. 단건 요청과 후속 요청의 상태 충돌은 그대로 409입니다.
- **재발방지**: 실제 PostgreSQL 통합 테스트로 정지·해제, 작성자 알림 중복 방지, 두 신고 처리와 감사 기록 4건, 후속 중복 요청 거부를 검증합니다. [운영 스펙](../plan/operations-console.md), [구조](../Architecture/operations-console.md).
- **수정 커밋**: `7f86cb6`

## 2. 공백만 있는 Ollama 스트림의 성공 처리

- **증상**: 공백과 줄바꿈 조각 뒤에 `done=true`를 보내면 정상 생성으로 완료됐습니다. 수정 전 `test_whitespace_only_stream_is_not_success`는 `LLMError`가 발생하지 않아 실패했습니다.
- **원인**: 스트림은 빈 문자열만 구분하고, 공백 문자열도 본문 수신으로 계산했습니다. 비스트리밍 경로는 이미 `strip()`으로 빈 응답을 확인해 두 경로의 기준이 달랐습니다.
- **해결**: 스트림 완료 시 공백 외의 본문을 실제로 받았는지 확인하고, 없으면 빈 응답 오류로 처리합니다. 정상 본문의 앞뒤 공백과 문단 구분은 그대로 전달합니다.
- **재발방지**: HTTP 모의 스트림에서 공백·줄바꿈·완료 신호 조합과 오류 후 추론 슬롯 반환을 검증합니다. 필수 컨텍스트와 Continuity 흐름은 유지합니다.
- **수정 커밋**: `c1850b4`

## 3. AI 실행 데이터가 Git 제외 규칙에 매칭되지 않음

- **증상**: `storyforge-ai/data/used_characters.json`이 추적되지 않은 파일로 계속 표시됐고 `git check-ignore --no-index`로도 제외되지 않았습니다.
- **원인**: 기존 `data/used_characters.json`, `data/chroma/` 패턴은 저장소 루트 기준이어서 실제 서비스 내부 경로와 맞지 않았습니다.
- **해결**: 실제 두 경로를 `.gitignore`에 추가했습니다. 실행 데이터 파일은 삭제하지 않았으며, 이름 풀 `names.json`은 계속 버전 관리합니다.
- **재발방지**: 두 실행 경로는 `git check-ignore --no-index`로, 이름 풀은 `git ls-files storyforge-ai/data`로 확인합니다.
- **수정 커밋**: `800d2f6`

## 4. 실행·검증 문서 점검

- `.env`에 적으면 모든 서비스가 자동 반영된다는 안내를 정정했습니다. Compose는 루트 `.env`의 치환 값을, FastAPI는 Pydantic 설정의 `.env`를 읽습니다. Spring Boot 로컬 프로세스에는 실행 셸이나 배포 도구가 환경 변수를 주입해야 합니다. Angular에는 백엔드 자격 증명을 전달하지 않습니다.
- 이전 제한 환경에서 Maven Wrapper의 캐시 접근과 시작 오류가 있었으나, 현재 환경에서는 `.\mvnw.cmd -v`가 정상 동작했습니다. 생성된 Wrapper는 수정하지 않았습니다.
- 기획 원본·과거 커밋 기록을 보존하고 현재 스펙·가이드·검증 결과와 문서 링크를 대조했습니다. 현재 테스트 결과는 [검증 문서](../vaildates/operations-console-release.md)에 모읍니다.
- 브라우저 검증은 이전 도구 안전 검사로 미완료인 상태를 유지합니다. 사용자가 이 제한을 기록하고 병합하도록 지시했으며, 이번 수정은 화면을 변경하지 않습니다.

## SMTP·실모델 후속 점검

- 실제 Gemma 첫 다중 챕터 실행은 2장에서 `done_reason=length`로 실패했습니다. `/api/ps`에서 컨텍스트 4096을 확인하고 요청·예열에 32768을 명시했습니다. 이후 합성 3장 모두 완료했지만 다른 모델 출력이므로 단일 원인으로 단정하지 않습니다. 출력 한도를 올려 잘림을 성공으로 취급하지 않았습니다.
- 원고 분량과 Continuity 품질 문제는 남았습니다. [실측·제한](../guidance/ollama-performance.md)과 [후속 체크리스트](../vaildates/local-followup.md)에 기록합니다.
- SMTP 일회용 토큰은 사용자 행 잠금으로 동시 소비를 제어하고 계정 버전으로 기존 JWT를 폐기합니다. 프로필 수정이 옛 비밀번호를 덮어쓰지 않도록 계정 낙관적 잠금을 추가했습니다.
- 기존 커뮤니티 테스트는 비밀번호 변경 후에도 이전 JWT를 사용했습니다. 새 폐기 정책에 따라 401을 검증하고 새 비밀번호로 재로그인하도록 수정했습니다.
- 메일 복구 요청에 저장된 JWT를 붙이면 이미 폐기된 토큰 때문에 링크를 사용할 수 없습니다. 공개 메일 요청은 인증 헤더를 붙이지 않고 성공 시 이전 로컬 세션을 지웁니다.
- SMTP 활성화 시 미인증 설정 이메일로 관리자 권한을 얻지 못하도록 이메일 인증 완료를 요구합니다. 실제 SMTP 수신·인증 전후 403/200을 통합 테스트로 확인합니다.
- 최신 사용자 지시는 브라우저 검증 전 병합 보류입니다. 과거 브라우저 미검증 병합 허용으로 새 화면을 병합하지 않습니다.
