# 신고·관리·이용약관·알림 스펙

> 기준: 사용자 요청 (2026-11-04). 기획서 §13(보안) 범위를 넓힌 기능이며 상태 머신은 바꾸지 않습니다. 커뮤니티 전체는 [community.md](community.md).

## 관리자

`ADMIN_EMAILS`(쉼표로 구분)에 적은 이메일의 계정이 관리자입니다. 비우면 관리자가 없습니다.

| 결정 | 이유 |
|------|------|
| DB 역할이 아니라 설정으로 지정 | 화면이나 API로 권한을 올릴 길을 만들지 않기 위해. 바꾸려면 서버 설정과 재시작이 필요 |
| 관리자 API는 403 | 존재를 숨길 이유가 없음. 다른 사용자의 리소스 404 규칙과 다름 |
| 관리자 계정은 정지할 수 없음 | 실수로 관리 수단을 잃지 않도록. 해임은 설정에서 |

이메일 소유 확인이 없으므로(아래 "없는 것"), **`ADMIN_EMAILS`의 주소로 다른 사람이 먼저 가입하면 그 사람이 관리자가 됩니다.** 운영 전에 관리자 계정을 먼저 만드세요.

## 신고

`POST /reports` `{targetType, targetId, reason, detail}`. 대상은 작품, 게시글, 댓글, 사용자이고 사유는 도배·광고, 욕설·괴롭힘·혐오, 부적절한 성적 내용, 불법·폭력 조장, 저작권 침해, 개인정보 노출, 기타입니다.

- 처리 전에 같은 대상을 다시 신고하면 새로 만들지 않습니다. 처리된 뒤에는 다시 신고할 수 있습니다.
- 내 글과 내 계정은 신고할 수 없고(409), 볼 수 없는 대상은 404입니다.
- **신고자는 작성자에게 알려지지 않습니다.**

## 관리자 처리

`GET /admin/reports?status=`, `PUT /admin/reports/{id}` `{action, note}`. 사용자 웹의 기존 화면은 `/admin`이고, 독립 운영 콘솔은 [operations-console.md](operations-console.md)를 따릅니다.

| 조치 | 효과 | 알림 |
|------|------|------|
| `HIDE` 숨김 | 작성자와 관리자만 봄. 같은 대상의 대기 신고를 모두 처리됨으로 | 작성자(사유 포함), 신고자 |
| `RESTORE` 복원 | 숨김 해제 | 작성자 |
| `DISMISS` 기각 | 같은 대상의 대기 신고를 모두 기각 | 신고자 |
| `SUSPEND` 작성자 정지 | 쓰기와 로그인 차단. 대기 신고를 처리됨으로 | 작성자(사유 포함), 신고자 |
| `UNSUSPEND` 정지 해제 | 정지 풀림 | 작성자 |

- **숨김은 삭제가 아닙니다.** 잘못 처리해도 복원할 수 있습니다.
- 숨긴 작품은 게시판, 프로필, 이슈, 패키지, Clone 네트워크, 공개 활동에서 빠지고 Clone·공유·통합 내보내기도 되지 않습니다. 작가에게는 안내와 함께 보입니다.
- 숨긴 댓글은 답글 흐름이 끊기지 않게 자리만 남기고 내용은 내려보내지 않습니다.
- 처리한 관리자와 메모는 신고 행에 남습니다. V11부터 단건·일괄 조치 모두 별도의 `admin_audit`에 남습니다. 기존 조치를 소급 생성하지는 않습니다.

## 계정 정지

JWT는 만료 전까지 유효하므로, `AccountGuardInterceptor`가 **쓰기 요청마다 DB에서 계정 상태를 확인**합니다. 정지되면 403이고, 삭제된 계정의 토큰은 401입니다. 읽기는 막지 않습니다. 정지 중에는 로그인도 403입니다. 정지해도 이미 쓴 글은 자동으로 숨기지 않습니다.

## 차단

`PUT`·`DELETE /users/{id}/block`, `GET /me/blocks`.

- 차단한 사람의 작품과 게시글은 내 게시판 목록에서 빠지고, 댓글은 보이지 않습니다 (그 댓글의 답글도 함께).
- 차단당한 사람은 내 글에 댓글을 달거나, 내 작품의 패키지 편입을 요청하거나, 나를 프로젝트에 초대할 수 없습니다.
- 차단한 사람의 행동은 알림이 오지 않습니다.
- 차단은 **내 화면과 상호작용만** 막습니다. 공개 작품은 여전히 공개입니다. 상대에게 차단 사실을 따로 알리지 않습니다.

## 이용약관

화면은 `/terms`이고 **문구는 법률 검토 전 초안입니다.** 공개 운영 전에 검토받아야 합니다.

- 가입할 때 동의가 필수입니다 (`acceptTerms`, 없으면 400).
- `TERMS_VERSION`을 올리면 기존 사용자는 다시 동의해야 게시, 패키지 생성, 라운지 글쓰기를 할 수 있습니다 (409, 상단 안내). 동의: `PUT /me/terms`. 읽기, 댓글, 원고 작성은 막지 않습니다.
- 문구를 바꾸면 `features/legal/terms.page.ts`의 시행일과 `TERMS_VERSION`을 함께 올립니다.

## 알림

상단 종. `GET /me/notifications`, `GET /me/notifications/unread-count`, `PUT /me/notifications/{id}/read`, `PUT /me/notifications/read-all`. 안 읽은 수는 1분마다 확인합니다 (실시간 전송은 없음).

| 종류 | 받는 사람 |
|------|-----------|
| 댓글, 답글 | 작품·글 주인, 원댓글 작성자 |
| Clone, 공유 | 작가 |
| 달성 | 작가. 단위를 처음 넘었을 때 한 번 |
| 업적 | 본인 |
| 패키지 편입 요청과 결과 | 그 작품의 작가, 패키지 주인 |
| 함께 창작 초대와 수락 | 초대받은 사람, 주인 |
| 관리자 조치 | 작성자, 신고자 |

내 행동은 나에게 오지 않습니다. 댓글 내용은 넣지 않습니다. 링크는 앱 안 경로만 저장하고, 화면도 `/`로 시작하는 경로만 따라갑니다. 원래 작업과 같은 트랜잭션이라 작업이 실패하면 알림도 남지 않습니다.

## 없는 것

- **이메일 인증, 비밀번호 재설정:** 메일 발송 수단(공급자, 발신 주소)을 먼저 정해야 합니다. 그때까지 다계정은 막지 못합니다.
- 금지 표현 목록(`CONTENT_BLOCKLIST`) 외의 자동 분류·신고 누적 자동 조치
- 자동 정지 만료 기간(현재는 해제할 때까지). 관리자 조치 감사 기록은 V11부터 제공
- 이의 제기 절차
