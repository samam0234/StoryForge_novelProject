# 커뮤니티 스펙

> 기준: 사용자 요청 (2026-11-03). 기획서 §5 "내보내기 및 공유 기능 중요", §6.4를 넓힌 기능이며 **상태 머신과 파이프라인 단계는 바꾸지 않습니다.**
> 기획서 Phase 1~3에 없던 범위라 기획서 본문은 고치지 않았고, 이 문서를 기준으로 삼습니다. 반영 여부는 [roadmap-progress.md](roadmap-progress.md)의 "결정 대기"에 있습니다.

## 게시판 구성

| 게시판 | 경로 | 내용 |
|--------|------|------|
| 롱품 | `/board/long` | 장편 |
| 숏품 | `/board/short` | 단편 |
| 패키지포지 | `/board/package` | 단독 작품(롱품·숏품)을 묶은 통합본 |
| 창작하기 | `/create` | 새 작품 시작 + **창작 라운지**(일반 커뮤니티 게시판: 자유, 창작 팁, 질문, 콜라보 모집, 작품 소개) |
| 이슈 | `/issues` | 달성 축하, 최근 7일 인기작, 새 작품 |

읽기는 로그인 없이 됩니다 (공유 링크를 바로 열 수 있어야 합니다). 쓰기, 추천, Clone, 내려받기는 로그인이 필요합니다.

## 비슷한 기능의 차이

| 기능 | 답하는 질문 | 무엇이 남는가 |
|------|-------------|---------------|
| **공유** | 이 작품을 **어디로 퍼뜨렸나** | 읽을 링크. 누가·어디에 공유했는지와 그 링크의 방문 수 (공유 그래프) |
| **Clone** | 이 작품을 **어떻게 이어 쓰나** | 내 프로젝트(창작 자료 사본). 원본과의 비교, 파생작 트리 (Clone 네트워크) |
| **내보내기** | 이 작품을 **파일로 어떻게 받나** | 파일. 기록을 남기지 않음 |
| **내 프로젝트** | 내가 **지금 뭘 써야 하나** | 비공개 작업실: 다음 할 일, 파이프라인 진행, 수동·에이전트 비율, 게시 여부, Clone 출처 |
| **게시판** | **무엇을 읽을까** | 공개된 게시본. 프로젝트와 독립된 스냅샷 |

## 게시

- `POST /projects/{id}/publish`. **승인된 챕터만** 게시본에 들어갑니다. 없으면 409. 프로젝트 하나에 작품 하나입니다.
- 게시본은 프로젝트의 스냅샷입니다. 프로젝트를 지워도 남고, 게시해도 파이프라인 상태는 바뀌지 않습니다.
- 공개 범위: `PUBLIC`(게시판·프로필), `UNLISTED`(링크만), `PRIVATE`(작가만, 다른 사람은 404).
- 수정: 작품 정보(`PUT /works/{id}`), 본문 직접 수정(`PUT /works/{id}/chapters/{n}`, 프로젝트 원고는 그대로), 프로젝트에서 다시 가져오기(`POST /works/{id}/sync`, 게시본에서만 고친 내용은 덮어씀). 본문이 바뀌면 리비전이 오르고 변경 이력에 남습니다.

## 작업 그래프

작업을 `activity_event`에 남기고, 주체를 수동(`MANUAL`)과 에이전트(`AGENT`)로 나눕니다.

| 주체 | 작업 |
|------|------|
| 에이전트 | Bible 생성, Outline 생성, 챕터 생성 |
| 수동 | Bible·Outline·챕터 직접 수정, 확정·승인, 게시, 게시본 수정 |

- 화면: 비율 막대(작업 횟수, 변경 글자), 날짜별 누적 막대, 작업 기록 표. **막대를 누르면 그날 작업만 표에 나옵니다.** 쉬는 날도 칸을 둡니다.
- 변경 글자는 앞뒤 공통 부분을 뺀 근사값입니다. 비율을 보여 주는 용도입니다.
- 요약에는 본문을 넣지 않습니다 ("3장 직접 수정"). 게시하면 게시 전 기록까지 공개되므로 게시 화면에서 안내합니다.
- 화면 아래 **작업 기록표**는 같은 기록을 git 로그처럼 위에서 아래로 보여 줍니다. 점을 누르면 그 기록 문단이 열립니다. 막대·비율·표는 그대로입니다.
- 프로필 활동 잔디의 칸을 누르면 그 날짜의 기록 문단이 잔디 바로 아래에 나옵니다.
- Clone으로 가져온 원고는 양쪽 어디에도 넣지 않습니다. 내가 쓴 것도, 내 에이전트가 쓴 것도 아니기 때문입니다.
- 마이그레이션 전 챕터 이력은 작업 기록으로 옮겼습니다. 수정본의 글자 수는 길이 차이로 근사했고, Bible·Outline 이력은 옮기지 않았습니다.

## Clone

`POST /works/{id}/clone` `{mode, title}`. 범위에 따라 시작 단계가 다릅니다.

| 범위 | 가져오는 것 | 시작 상태 | 하는 일 |
|------|-------------|-----------|---------|
| `WORLD` 세계관 | Story Bible | `BIBLE_DRAFT` | 같은 세계에서 새 이야기 |
| `PLOT` 플롯 | Bible + Outline | `OUTLINE_DRAFT` | 줄거리를 고쳐 새로 생성 |
| `FULL` 전체 원고 | Bible + Outline + 게시 원고 | `CHAPTER_REVIEW` | 원고를 앞 장부터 다시 검토·승인 |

- **전이 규칙은 그대로입니다.** 정한 것은 시작 상태뿐이며, 이후 전이는 `PipelineStateMachine`을 따릅니다. [pipeline-state-machine.md](../Architecture/pipeline-state-machine.md)
- `FULL`도 자동 승인하지 않습니다. 복제 원고는 모두 Draft로 들어가고 앞 장부터 승인합니다. 이 프로젝트 기준의 Continuity 결과가 없으므로 승인할 때 한 번 더 확인받고, 재생성하면 검증합니다.
- 작가의 Clone 정책: `OPEN`(모두), `WORLD_ONLY`(세계관만), `CLOSED`(불가, 설정집도 비공개). 작가 본인은 정책과 관계없이 됩니다. 패키지는 Clone하지 않습니다.
- 원본 비교(`GET /projects/{id}/upstream`, "원본 비교" 탭): 챕터별로 같음·달라짐과 단어 단위 Diff, 원본이 몇 리비전 앞섰는지. 원본이 지워지거나 비공개가 되면 비교만 막히고 내 프로젝트는 그대로입니다.
- Clone 네트워크(`GET /works/{id}/network`): 원작부터 **공개 게시된** 파생작 트리와 Clone 기록. Clone한 프로젝트를 게시하면 원작으로 표시됩니다.

## 공유

`POST /works/{id}/shares` `{channel, target}` → 전용 토큰 링크(`/works/{id}?s=토큰`). 공유하면 **공유 그래프 탭으로 바로 이동**합니다.

- 공유 그래프(`GET /works/{id}/shares`): 유저 → 채널 연결 그래프와 누가·어디에·방문 수 표. **이름과 입력한 위치는 공개**되므로 입력 화면에서 안내합니다. 토큰은 응답에 넣지 않습니다.
- 방문은 `POST /shares/{token}/visit`로 셉니다. 같은 브라우저 세션에서는 한 번만 보내고, IP당 요청을 제한합니다. 서버가 방문자를 구분하지는 않으므로 참고용 수치입니다.
- X, Facebook, 이메일은 작성 화면을 열 수 있고 나머지는 링크를 복사합니다 (카카오 SDK는 앱 키가 필요해 넣지 않았습니다).

## 내보내기

`md`, `txt`, `docx`, `pdf`, `html`, `epub`, `odt`, `rtf`. 프로젝트(`/projects/{id}/export`)와 작품(`/works/{id}/export`)이 같은 코드를 씁니다. 작품은 로그인이 필요하고 작가가 막으면(`downloadable=false`) 다른 사람은 409입니다. 패키지는 독서 순서대로 합칩니다.

새 형식은 라이브러리 없이 만듭니다 (`ManuscriptWriters`). 원고의 HTML 태그는 실행되지 않게 글자로 남깁니다. **EPUB, ODT, RTF는 구조 검사까지만 했고, 실제 전자책 뷰어·LibreOffice·Word에서 열어 보지는 못했습니다** (이 환경에 없음).

## 패키지포지

단독 작품을 묶어 연결된 세계를 만듭니다. `POST /packages`. **내가 직접 게시한 작품이 하나 이상** 있어야 만들 수 있습니다.

| 유형 | 뜻 |
|------|----|
| 유니버스 | 같은 세계관을 공유 |
| 옴니버스 | 독립된 이야기를 한 주제로 |
| 앤솔러지 | 여러 작가의 선집 |
| 사가 | 시간 순서로 이어지는 연대기 |
| 크로스오버 | 다른 세계의 인물이 만남 |
| 스핀오프 | 원작과 외전 묶음 |
| 커스텀 | 직접 정함 |

- 독서 순서(끌어서 변경), 작품별 역할(본편, 외전, 프리퀄, 속편, 스핀오프, 막간), 공용 세계관 노트
- 연결 지도: 작품 사이의 관계(이어짐, 같은 세계, 인물 공유, 같은 사건, 언급)와 설명
- 통합 인물 사전: 이름이 같은 인물을 교차 등장으로 묶습니다. Clone을 막은 작품의 설정집은 넣지 않습니다. **이름이 같다고 같은 인물이라는 보장은 없습니다.**
- 통합 내보내기: 독서 순서대로 한 파일
- **다른 작가의 작품은 그 작가가 승인해야** 독자에게 보입니다 ("내 작품 관리"의 편입 요청). 그 작가는 언제든 뺄 수 있습니다.
- 패키지 안에 패키지는 넣을 수 없습니다.

## 추천·댓글·라운지

- 추천은 사용자당 한 번이고 두 번 눌러도 한 번입니다. **자기 작품은 추천할 수 없습니다** (달성 기록 조작 방지).
- 댓글은 답글 한 단계까지. 수정은 작성자만, 삭제는 작성자와 작품·글 주인입니다. 내용은 글자로만 보여 줍니다.

## 이슈

`GET /issues`. 최근 7일 점수(추천 3, 댓글 2, Clone 5, 공유 2) 순 인기작, 달성 축하, 새 작품.

| 달성 | 단위 |
|------|------|
| 하루(24시간) 추천 | 100, 1,000, 10,000 |
| 누적 추천 | 100, 1,000, 10,000 |
| 누적 Clone | 10, 100, 1,000 |
| 누적 공유 | 10, 100, 1,000 |
| 누적 조회 | 1,000, 10,000, 100,000 |

같은 작품·지표·단위는 한 번만 기록합니다.

## 프로필과 계정

- 프로필(`/users/{id}`): 소개, 공개 작품, 활동 잔디, 활동 내역, 업적. **이메일은 공개하지 않습니다.**
- 활동 잔디: 최근 53주. 하루 활동 1~2건, 3~5건, 6~10건, 11건 이상으로 진해집니다. 칸을 누르면 그날 활동이 나옵니다. 추천은 눌렀다 취소하며 부풀릴 수 있어 세지 않습니다.
- 활동 내역: 다른 사람에게는 공개 작품·게시글에 연결된 기록만 보입니다. 비공개 프로젝트 활동은 잔디의 건수로만 집계됩니다.
- 업적 23종: 활동이 커밋된 뒤 계산합니다. 계산이 실패해도 파이프라인 작업은 되돌아가지 않습니다.
- 계정 설정(`/me/settings`): 이름, 소개, 웹사이트, 아바타 색, 비밀번호 변경, 계정 삭제. 계정을 지우면 프로젝트·작품·댓글이 지워지고, 다른 사람의 Clone은 출처 이름과 함께 남습니다.
- 내 작품 관리(`/me/works`): 게시한 작품의 수정·삭제, 패키지 편입 요청 처리.

## AI 가이드챗

상단의 가이드 버튼. Angular → Spring Boot(`POST /guide/chat`) → FastAPI(`POST /internal/guide/chat`). 로그인이 필요하고 AI 생성과 같은 요청 제한을 받습니다.

- 명령어: `/도움말`, `/상태`(내 최근 프로젝트의 다음 단계), `/시작`, `/바이블`, `/아웃라인`, `/챕터`, `/검증`, `/게시`, `/클론`, `/공유`, `/패키지`, `/내보내기`, `/게시판`, `/이슈`, `/프로필`, `/그래프`, `/콜라보`. 명령어는 LLM을 호출하지 않습니다.
- 자유 질문: mock에서는 키워드로 안내를 찾고, `anthropic`에서는 모델이 답합니다. **실제 모델 호출은 검증하지 못했습니다.**
- 이동 버튼은 항상 서버의 표에서 만듭니다. 모델 응답에 든 주소는 버튼이 되지 않습니다.
- **Codicomperchat 연결**: `/콜라보`가 `CODICOMPERCHAT_URL`로 새 창을 엽니다 (확인 후). 주소가 비어 있으면 버튼을 표시하지 않습니다. 현재는 링크 이동이며, **MCP나 커넥터 연동은 구현하지 않았습니다** (상대 사이트의 주소와 규격이 필요합니다).

## 아직 없는 것

- 신고, 관리자, 차단, 욕설 필터. **공개 운영 전에 필요합니다.**
- 이용약관, 게시물 권리 안내, Clone 시 저작권 조건
- 알림(달성, 편입 요청, 댓글)은 이슈 게시판과 관리 화면에서만 보입니다
- 원본의 변경을 내 Clone으로 가져오는 병합 (현재는 비교만)
- 패키지 전체의 Continuity 검사
- 조회수 중복 제거 (새로고침도 셉니다)

## 함께 창작

파이프라인 상태와 전이 규칙은 바꾸지 않습니다. 초대를 수락한 사람만 그 프로젝트의 원고를 봅니다.

| 하는 일 | 누가 |
|---------|------|
| 이메일로 초대, 초대 취소, 게시, 설정 변경, 프로젝트 삭제 | 주인 |
| 초대 수락·거절 | 초대받은 사람. 수락 전에는 원고가 보이지 않습니다 |
| 원고 수정, 작업 커밋 | 주인과 수락한 참여자 |

- 초대 목록은 창작하기(`/create`)에 나옵니다. 수락하면 내 프로젝트 목록에도 `COLLABORATOR`로 나타납니다.
- 작업 커밋(`POST /projects/{id}/commits`)은 메시지, 대상(Bible·Outline·챕터), 붙여 넣은 문장, 그 문장 안의 시작·끝 글자 위치를 남깁니다. 직전 커밋을 부모로 이어 git 기록표로 보여 주고, 점을 누르면 표시한 구간이 칠해집니다. 링크를 누르면 그 화면 위에도 같은 구간이 나옵니다.
- 공개 작업 그래프에는 "작업 커밋"이라는 요약만 이어집니다. 메시지와 인용 문장은 참여자 API에만 있습니다.
- 참여자가 아니면 프로젝트는 404입니다. 참여자가 삭제·게시·설정·초대를 하면 409입니다.
