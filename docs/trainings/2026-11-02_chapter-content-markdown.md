# 챕터 본문 저장 형식을 Markdown으로 정한 이유

- 일자: 2026-11-02
- 관련 기획서 절: §6.4 (리치 텍스트 에디터, 내보내기, Diff), §9.2 (TipTap)

## 질문

TipTap을 넣으면 편집 결과를 어떤 형식으로 저장할 것인가. 기존 데이터와 AI 출력은 평문이다.

## 선택지

- A: HTML (TipTap 기본)
- B: TipTap JSON
- C: Markdown

## 결정과 이유

**C. Markdown.**

- AI 출력(문단을 빈 줄로 구분한 평문)이 그대로 유효한 Markdown이라, 생성본과 편집본을 형식으로 구분할 필요가 없다. 기존 데이터 변환도 필요 없다.
- 내보내기(§6.4)의 Markdown은 그대로, DOCX·PDF는 파서로 구조를 읽어 만들 수 있다.
- 생성 히스토리 Diff(§6.4)가 사람이 읽을 수 있는 줄 단위로 나온다.

## 버린 선택지와 이유

- HTML: Diff에 태그가 섞이고, 생성본(평문)과 편집본(HTML)을 구분해야 한다.
- JSON: Diff와 내보내기마다 변환이 필요하고, DB에서 사람이 읽기 어렵다.

## 감수한 점

- 문단 안의 줄바꿈 하나는 Markdown에서 공백으로 합쳐진다. 그래서 챕터 프롬프트에 "문단은 빈 줄로 구분"을 넣었다.
- 편집 후에는 에디터가 Markdown을 정규화하므로 원문과 기호 이스케이프가 조금 달라질 수 있다.
- Story Bible 필드는 구조화된 짧은 텍스트라 기존 입력란을 유지한다. 리치 텍스트는 챕터 본문에만 적용한다.

## 다시 검토할 조건

표, 이미지, 주석처럼 Markdown으로 옮기기 어려운 서식이 필요해질 때.
