# 운영 콘솔 실행과 검증

## 전제

Node.js, JDK, Python, Docker 버전은 [CURRENT_STACK](../plan/CURRENT_STACK.md)을 따릅니다. DB·백엔드가 실행 중이어야 합니다. 운영자는 기존 사용자 웹에서 계정을 먼저 확보하고 그 이메일을 백엔드 `ADMIN_EMAILS`로 지정합니다. 콘솔은 가입 기능을 제공하지 않습니다.

## 실행

백엔드 실행 셸에서 환경 변수를 설정한 후 재시작합니다. 사용자 웹과 콘솔은 같은 Spring Boot API를 사용합니다.

```powershell
$env:ADMIN_EMAILS = '본인 운영자 이메일'
$env:CONSOLE_ORIGIN = 'http://localhost:4201'
```

별도 터미널의 `storyforge-console` 폴더에서 실행합니다.

```sh
npm ci
npm start
```

`http://localhost:4201`에서 운영자로 로그인합니다. 일반 계정은 진입할 수 없습니다. 운영 환경에서는 실제 콘솔 도메인, TLS, SPA fallback, `/api` 백엔드 프록시를 구성합니다. 개발 프록시 설정이 배포 산출물에 포함되는 것은 아닙니다.

## 기대 결과

1. 운영 현황의 회원·프로젝트·작품·신고 수와 상태별 분포가 표시됩니다.
2. 신고 관리에서 상태를 선택하고 신고를 체크한 후 조치·사유를 입력할 수 있습니다. 같은 대상 신고는 한 번만 조치합니다.
3. 회원 관리에서 이메일·이름을 검색하고 이용 상태로 거를 수 있습니다. 운영자 계정의 정지 버튼은 비활성입니다.
4. 정지·해제를 적용하면 알림과 감사 기록이 함께 남습니다. 같은 상태로 다시 조치하면 409입니다.
5. 감사 기록에서 운영자 ID별로 조회할 수 있습니다. 이 화면에서는 수정·삭제할 수 없습니다.

실패한 일괄 요청은 일부만 반영되지 않습니다. 409가 나오면 새로고침하여 다른 운영자의 처리 결과를 확인합니다. 401은 다시 로그인하고, 403은 서버 관리자 설정을 확인합니다.

## 검증 명령

```sh
npm test
npm run build
```

DB 트랜잭션과 권한 검증은 `storyforge-backend`에서 Docker 실행 후 `./mvnw test`로 확인합니다. 상세 결과와 브라우저 확인 제한은 [검증 문서](../vaildates/operations-console-release.md)에 있습니다.
