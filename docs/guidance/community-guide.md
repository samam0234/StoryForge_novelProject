# 커뮤니티 운영 가이드

처음 켤 때 설정할 값과, 기능이 동작하는지 손으로 확인하는 절차입니다. 스펙은 [../plan/community.md](../plan/community.md), [../plan/moderation.md](../plan/moderation.md)에 있습니다.

## 전제

- [local-dev-setup.md](local-dev-setup.md)대로 전체 스택이 실행 중
- 기본값은 mock 생성기라 API 키 없이 확인할 수 있습니다

## 환경 변수 (백엔드)

| 변수 | 기본값 | 언제 바꾸나 |
|------|--------|-------------|
| `ADMIN_EMAILS` | (없음) | 신고를 처리할 관리자 이메일. 쉼표로 구분 |
| `TERMS_VERSION` | `2026-11-04` | 약관 문구를 바꿀 때. 기존 사용자는 다시 동의해야 게시 가능 |
| `COMMUNITY_ZONE` | `Asia/Seoul` | 작업 그래프와 활동 잔디의 날짜 기준 |
| `RATE_LIMIT_COMMUNITY_PER_MINUTE` | `60` | 글·댓글·공유·Clone·신고 분당 한도 |
| `CODICOMPERCHAT_URL` | (없음) | 가이드챗 `/콜라보`의 이동 주소. 비우면 버튼을 표시하지 않음 |

## 관리자 지정

```bash
ADMIN_EMAILS=admin@example.com ./mvnw spring-boot:run     # PowerShell: $env:ADMIN_EMAILS="admin@example.com"
```

**기대 결과:** 그 이메일로 로그인하면 왼쪽 메뉴에 "신고 관리"가 나오고 `/admin`이 열립니다. 다른 계정은 `/admin`에서 첫 화면으로 돌아갑니다.

## 작품 게시부터 Clone까지

1. 새 프로젝트 → Bible 생성·확정 → Outline 생성·확정 → 챕터 생성·승인
2. 프로젝트의 **게시** 탭 → 게시. 작품 화면으로 이동합니다
3. 다른 계정으로 작품 화면 → **Clone** → 범위 선택. 내 프로젝트가 만들어집니다

**기대 결과:** 전체 원고 Clone은 챕터 검토 단계에서 시작하고, 승인할 때 요약과 Continuity를 다시 만듭니다. 원본이 바뀌면 **원본 비교** 탭에 앞선 리비전이 표시되고 원본으로 덮어쓸 수 있습니다.

## 신고 처리

1. 다른 계정으로 작품의 **신고** → 사유 선택
2. 관리자로 **신고 관리** → 메모를 적고 **숨김**

**기대 결과:** 작품이 게시판에서 빠지고 다른 사람에게는 404입니다. 작가에게는 사유가 담긴 알림이 오고, 작품 화면에 숨김 안내가 나옵니다. **처리됨** 탭에서 **복원**하면 돌아옵니다.

## 패키지 검사

1. 패키지포지에서 작품을 두 개 이상 묶습니다
2. **전체 Continuity 검사** → 검사 실행

**기대 결과:** 점수와 문제 목록이 나옵니다. mock에서는 규칙 검사(같은 이름 인물의 설명 차이, 연결되지 않은 작품)만 합니다.

## 실패하면

| 증상 | 원인 |
|------|------|
| 게시가 409 "이용약관에 동의해야" | 약관 도입 전 계정이거나 `TERMS_VERSION`이 올라갔습니다. `/terms`에서 동의합니다 |
| 쓰기가 403 "이용이 정지된 계정" | 관리자가 정지했습니다. 신고 관리에서 해제합니다 |
| 승인이 409 "심각한 연속성 이슈" | 수정본 재검증 결과입니다. 리포트를 확인하고 다시 승인하면 진행됩니다 |
| 승인이 502 | AI 서비스가 꺼져 있습니다. 수정본은 재검증이 필요해 승인되지 않습니다 |
| "신고 관리" 메뉴가 없음 | `ADMIN_EMAILS`를 바꾼 뒤 백엔드를 다시 시작했는지 확인합니다 |
