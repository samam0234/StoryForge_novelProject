# storyforge-console

StoryForge의 **운영 콘솔**입니다. 운영자가 서비스 현황을 보고, 신고를 처리하고, 회원을 정지·해제하고, 누가 무엇을 했는지 감사 기록을 확인하는 독립 Angular 앱입니다.

| | |
|---|---|
| **기술** | Angular 21.2 (standalone 컴포넌트, signals), RxJS 7.8, TypeScript 5.9 |
| **주소** | 개발 http://localhost:4201 |
| **호출 대상** | Spring Boot `/api/v1`만. LLM과 FastAPI는 호출하지 않습니다 |
| **로그인** | `ADMIN_EMAILS`에 등록된 **기존 계정**만. 가입 화면은 없습니다 |
| **테스트** | Vitest 8건 + 프로덕션 빌드 |

사용자 웹([storyforge-frontend](../storyforge-frontend/README.md))과 **따로 빌드하고 따로 배포**합니다. 의존성(`package-lock.json`), 테스트, 빌드 산출물을 공유하지 않습니다. 운영 도구를 일반 사용자가 받는 번들에 섞지 않고, 운영자만 접근하는 주소에 둘 수 있게 하기 위해서입니다.

## 실행

### 준비물

| 항목 | 조건 |
|------|------|
| Node.js | 24.14 이상 ([확정 스택](../docs/plan/CURRENT_STACK.md)) |
| 백엔드와 PostgreSQL | 실행 중 |
| 운영자 계정 | 사용자 웹에서 먼저 가입한 계정 |

### 1. 운영자 지정

콘솔에는 가입이나 권한 부여 화면이 없습니다. 운영자는 **백엔드의 환경 변수**로만 정합니다.

```powershell
# 백엔드를 실행하는 셸에서 (PowerShell)
$env:ADMIN_EMAILS = '운영자@example.com'
$env:CONSOLE_ORIGIN = 'http://localhost:4201'
```

```bash
# bash
ADMIN_EMAILS=운영자@example.com ./mvnw spring-boot:run
```

값을 바꾸면 백엔드를 다시 시작해야 적용됩니다.

> **계정을 먼저 만드세요.** 메일 인증을 켜지 않은 환경에서는 `ADMIN_EMAILS`의 주소로 먼저 가입한 사람이 관리자가 됩니다.
> 메일 인증을 켠 환경(`MAIL_ENABLED=true`)에서는 그 계정이 사용자 웹에서 **이메일 인증을 끝낸 뒤에야** 관리자 권한이 생깁니다.

### 2. 콘솔 실행

```bash
cd storyforge-console
npm ci
npm start             # http://localhost:4201
```

개발 서버는 [proxy.conf.json](proxy.conf.json)으로 `/api`를 백엔드 8080에 넘깁니다.

### 명령어

| 하려는 일 | 명령 | 결과 |
|-----------|------|------|
| 개발 서버 | `npm start` | http://localhost:4201 |
| 단위 테스트 | `npm test` | Vitest 8건 |
| 프로덕션 빌드 | `npm run build` | `dist/storyforge-console/browser/` |

## 화면

| 경로 | 화면 | 하는 일 |
|------|------|---------|
| `/login` | 로그인 | 운영자 로그인. 일반 계정이면 권한 오류를 안내합니다 |
| `/` | 운영 현황 | 회원, 정지 회원, 프로젝트, 작품, 대기 신고 수와 프로젝트의 파이프라인 상태별 분포 |
| `/reports` | 신고 관리 | 상태별 신고 목록, 신고 내용·작성자·신고자 확인, 여러 건을 골라 한 번에 조치 |
| `/users` | 회원 관리 | 이름·이메일 검색, 정지 상태 필터, 정지·해제 |
| `/audit` | 감사 기록 | 운영 조치 이력, 운영자별 조회. 수정·삭제할 수 없습니다 |

**신고 조치**는 다섯 가지입니다.

| 조치 | 효과 |
|------|------|
| `HIDE` 숨김 | 작성자와 관리자만 보게 됩니다. 삭제가 아니라 복원할 수 있습니다 |
| `RESTORE` 복원 | 숨김을 풉니다 |
| `DISMISS` 기각 | 조치 없이 신고를 닫습니다 |
| `SUSPEND` 작성자 정지 | 쓰기와 로그인을 막습니다 |
| `UNSUSPEND` 정지 해제 | 정지를 풉니다 |

화면이 지키는 동작은 다음과 같습니다.

- 목록은 한 페이지에 20건입니다 (서버 상한 50건).
- 빈 목록, 불러오는 중, 실패를 구분해 보여 줍니다.
- 쓰는 동안에는 버튼을 막아 중복 제출을 방지하고, 실패하면 성공 메시지를 띄우지 않습니다.
- 일괄 조치에는 사유가 필수입니다. 이 사유가 대상자에게 가는 알림에 들어갑니다.
- 운영자 계정의 정지 버튼은 비활성입니다. 서버도 관리자 정지를 거부합니다.

## 권한이 확인되는 방식

화면의 검사는 **편의**이고, 실제 방어선은 서버입니다.

| 단계 | 누가 | 무엇을 |
|------|------|--------|
| 로그인 | 콘솔 | 로그인 응답과 `/auth/me`의 관리자 여부를 확인합니다. 아니면 들여보내지 않습니다 |
| 메뉴 이동 | 콘솔 (`adminGuard`) | 화면을 옮길 때마다 권한을 다시 확인합니다 |
| 모든 API 요청 | **백엔드** | 서비스 진입점마다 관리자 여부를 다시 확인합니다. 일반 회원은 403 |

- 토큰은 탭의 `sessionStorage`에 둡니다. 탭을 닫으면 사라집니다.
- 401을 받거나 로그아웃하면 토큰을 지웁니다.
- 비밀번호를 바꾸거나 재설정하면 기존 토큰이 폐기되므로 콘솔도 다시 로그인해야 합니다.
- API는 상대 경로 `/api/v1`만 씁니다. 다른 출처로 요청하지 않습니다.

## 조치가 안전하게 처리되는 방식

여러 운영자가 동시에 일해도 결과가 꼬이지 않도록 서버가 보장합니다. 콘솔은 그 결과를 그대로 보여 줍니다.

- **전부 아니면 전무:** 일괄 조치(최대 50건)는 한 트랜잭션입니다. 중간에 하나라도 실패하면 앞선 변경, 신고 상태, 알림, 감사 기록이 모두 되돌려집니다.
- **직렬화:** 단건·일괄·회원 직접 조치가 같은 DB 잠금 행을 잡습니다. 백엔드가 여러 대여도 운영 조치끼리는 순서대로 처리됩니다.
- **중복 방지:** 같은 대상에 대한 여러 신고는 한 번만 조치합니다. 같은 작성자의 여러 글을 한 번에 정지해도 계정 변경과 작성자 알림은 한 번입니다.
- **충돌은 409:** 이미 처리된 신고를 다시 닫거나, 이미 숨긴 글을 숨기거나, 이미 풀린 정지를 풀려고 하면 409입니다. 새로고침해서 다른 운영자의 처리 결과를 확인합니다.
- **감사 기록:** 조치와 같은 트랜잭션에 남습니다. 계정이나 신고가 지워져도 기록은 남습니다.

| 응답 | 뜻 | 할 일 |
|------|----|-------|
| 401 | 세션 만료 | 다시 로그인 |
| 403 | 관리자가 아님 | 백엔드의 `ADMIN_EMAILS`와 이메일 인증 여부 확인 |
| 404 | 없는 대상 | 목록 새로고침 |
| 409 | 다른 요청이 먼저 처리함 | 새로고침 후 결과 확인 |
| 400 | 입력 오류 | 사유 등 입력 확인 |

스펙은 [operations-console.md](../docs/plan/operations-console.md), 잠금 흐름은 [Architecture/operations-console.md](../docs/Architecture/operations-console.md)에 있습니다.

## 구조

화면이 다섯 개인 작은 앱이라 기능마다 파일 하나로 둡니다.

```
storyforge-console/
├── proxy.conf.json       # 개발 서버 /api → 백엔드 8080
├── angular.json          # 빌드 설정
└── src/
    ├── main.ts, index.html, styles.css
    └── app/
        ├── app.routes.ts # 경로. 로그인을 뺀 모든 화면에 adminGuard
        ├── core/
        │   ├── api.ts    # 백엔드 API 계약과 호출
        │   └── auth.ts   # 세션, 인터셉터, 가드
        ├── features/     # login, overview, reports, users, audit
        ├── layout/       # shell — 운영 메뉴, 세션 표시
        └── shared/       # pager — 페이지 이동
```

사용자 웹과 코드를 공유하지 않습니다. 백엔드의 응답 형식이 바뀌면 `core/api.ts`를 함께 고칩니다.

## 테스트

```bash
npm test          # Vitest 8건
npm run build     # 반드시 함께 확인
```

| 다루는 것 | 다루지 않는 것 |
|-----------|----------------|
| 권한 확인, 토큰 경계, 만료 처리 (`core/auth.spec.ts`) | 실제 서버의 권한 검사 |
| 신고 일괄 처리 화면 (`features/reports.spec.ts`) | 트랜잭션의 원자성, 동시 조치 |

서버 쪽 권한·원자성·동시 조치는 백엔드의 `ConsoleIntegrationTest`가 실제 PostgreSQL로 확인합니다 (`storyforge-backend`에서 `./mvnw test`).

## 배포

콘솔은 루트의 `docker-compose.deploy.yml`에 **포함되어 있지 않습니다.** 따로 호스팅해야 하며, 다음을 구성해야 합니다.

1. `npm run build`의 산출물 `dist/storyforge-console/browser`를 정적 파일로 제공합니다.
2. `/api`를 Spring Boot로 프록시합니다. 개발용 `proxy.conf.json`은 배포 산출물에 들어가지 않습니다.
3. 그 밖의 경로는 `index.html`로 돌려 SPA 라우팅이 동작하게 합니다.
4. 백엔드의 `CONSOLE_ORIGIN`을 실제 콘솔 주소로 지정합니다. 운영 프로필에서는 경로·와일드카드·후행 슬래시가 없는 HTTPS 출처 하나여야 하고, 아니면 백엔드가 시작하지 않습니다.
5. 운영자만 접근할 수 있도록 네트워크나 앞단 프록시에서 접근을 제한하는 것을 권합니다.

절차는 [guidance/operations-console.md](../docs/guidance/operations-console.md)에 있습니다.

## 문제 해결

| 증상 | 원인 / 해결 |
|------|-------------|
| 로그인은 되는데 권한 오류 | 그 이메일이 백엔드 `ADMIN_EMAILS`에 없거나, 바꾼 뒤 백엔드를 다시 시작하지 않았습니다 |
| 메일을 켠 뒤로 관리자가 403 | 이메일 인증이 끝나지 않았습니다. 사용자 웹의 계정 설정에서 인증합니다 |
| 요청이 CORS 오류 | 백엔드 `CONSOLE_ORIGIN`이 콘솔 주소와 다릅니다 |
| 조치가 409 | 다른 운영자가 먼저 처리했습니다. 새로고침합니다 |
| 비밀번호를 바꾼 뒤 튕김 | 기존 토큰이 폐기된 것입니다. 다시 로그인합니다 |
| 화면이 비어 있고 API 오류 | 백엔드(8080)가 꺼져 있습니다 |

## 하지 않는 것

- **자동 정지, 작품 영구 삭제, 관리자 권한 변경은 제공하지 않습니다.** 권한은 서버 설정으로만 바뀝니다.
- 운영 현황은 조회 시점의 집계입니다. 실시간 모니터링이나 AI 서버 가용성 판정이 아닙니다.
- 감사 기록은 이 기능 도입 전의 조치를 소급해 만들지 않습니다. 수정·삭제 API는 없지만 DB 관리자의 변경까지 막는 불변 저장소는 아닙니다.
- API 키나 DB 자격 증명을 이 앱에 넣지 않습니다.
- **실제 브라우저에서 확인하지 못했습니다.** 자동 테스트와 빌드는 통과했지만 이를 화면 검증으로 간주하지 않습니다. 확인 목록은 [operations-console-release.md](../docs/vaildates/operations-console-release.md)에 있습니다.
